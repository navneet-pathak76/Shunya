# SUNYA Documentation

This directory is the project knowledge base. Documentation is intentionally separated from implementation so product decisions can be reviewed before code is written.

## Volumes

1. `product/` — product vision, scope, personas, use cases and requirements
2. `architecture/` — system, application and integration architecture
3. `ux/` — information architecture, navigation, flows and design system guidance
4. `database/` — entities, relationships, data lifecycle and migrations
5. `api/` — API conventions, contracts and endpoints
6. `ai/` — AI orchestration, context, memory, safety and evaluation
7. `health/` — health-domain specifications and safety boundaries
8. `security/` — threat model, privacy and security controls
9. `deployment/` — environments, CI/CD and hosting
10. `research/` — research notes and future investigations

## Documentation rule

Every major implementation decision should have a corresponding specification or Architecture Decision Record before it becomes difficult to change.
